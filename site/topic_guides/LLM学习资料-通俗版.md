## 1. 大语言模型为什么会出现

### 1.1 从“会预测下一个词”到“看起来会做任务”

GPT 系列的基础目标很朴素：给前面的词，预测下一个词。例如：

```text
The weather is very nice ...
```

模型训练时并不是直接学“翻译”“问答”“写论文标题”这些任务，而是在海量文本里反复学习：

```text
前文 -> 下一个 token
```

听起来很简单，但如果训练数据足够大，模型为了把下一个 token 预测好，就不得不学到很多东西：

- 词语搭配和语法结构；
- 常识和百科知识；
- 问答、翻译、摘要、推理题在文本中通常怎么写；
- 不同领域的表达风格；
- 代码、数学、论文、教程、对话等格式。

所以 GPT-2 课件里提到“零样本任务迁移”：模型原本只训练续写，但因为训练语料中有大量自然语言形式的任务，它能在没专门微调的情况下尝试阅读理解、翻译、摘要和问答。

### 1.2 缩放定律：为什么模型要变大

课件讲到 Chinchilla Scaling Law，用三个量描述训练规模：

| 符号 | 含义 | 通俗理解 |
|---|---|---|
| `N` | 模型参数量 | 模型容量有多大 |
| `D` | 训练数据量 | 模型看过多少 token |
| `C` | 计算量 | 训练总共花了多少算力 |

课件给出的经验关系是：

```text
C 约等于 6ND
```

直觉是：模型不能太小，否则装不下太多规律；模型也不能只一味变大，如果数据太少，大容量用不起来。好的训练不是单纯堆参数，而是在参数量、数据量和计算量之间做平衡。

可以把模型想成学生：

- 参数量像脑容量和解题模板数量；
- 数据量像做过多少题、读过多少材料；
- 计算量像学习时间和训练强度。

学生太小、材料太多，学不完；学生很大但只看几页纸，也学不出稳定能力。大模型成功的关键是三者一起扩。

### 1.3 涌现能力：为什么大到一定程度会“突然会”

课件用表情符号猜电影的例子说明涌现能力：有些能力在小模型上几乎看不到，模型变大后才表现出来。它不是每增加一点参数都线性变好，而可能像“跨过门槛”。

涌现能力可以理解为：复杂任务往往需要很多小能力同时到位。

例如看表情猜电影，模型可能要同时具备：

- 识别表情含义；
- 知道电影名；
- 把表情组合和电影情节联系起来；
- 按用户的问题格式输出答案。

小模型可能每个环节都差一点，最后整体失败；大模型如果这些环节都接近可用，答案就会突然变得像样。

考试时要注意：涌现能力不是说模型产生了神秘智能，而是说某些任务指标在规模变大后出现明显跃迁。它和训练数据、评测方式、提示方式都有关。

## 2. Transformer 如何支撑 LLM

### 2.1 GPT 为什么常用 Decoder-only

课件把 BERT 和 GPT 放在“大模型时代的序幕”里：

| 模型类型 | 架构 | 训练目标 | 更擅长的方向 |
|---|---|---|---|
| BERT | Encoder-only | Masked Language Model、Next Sentence Prediction | 理解、分类、抽取、匹配 |
| GPT | Decoder-only | 自回归预测下一个 token | 生成、对话、续写、复杂指令响应 |

现代聊天大模型大多更接近 GPT 路线，因为聊天和写作本质上是“根据上下文继续生成”。给它一段输入，它逐 token 生成回复：

```text
用户问题 + 历史上下文 -> 第 1 个输出 token -> 第 2 个输出 token -> ...
```

这就要求模型不能在生成时偷看未来，所以 Decoder-only 的因果自注意力很合适：当前位置只能看前面的 token。

### 2.2 Transformer 的骨架为什么耐用

Transformer 能支撑 LLM，主要因为它有三个优势：

1. Self-Attention 可以让任意两个 token 直接交互，不像 RNN 那样必须一步一步传递信息。
2. 训练时能并行处理序列中的多个位置，适合大规模 GPU 训练。
3. 层数、宽度、注意力头数、FFN 维度都可以扩大，工程上容易扩展。

对 LLM 来说，最关键的是“能在长上下文里建立关系”。例如用户让模型分析一篇论文，模型要把开头的研究问题、中间的实验方法、后面的结论联系起来。Self-Attention 提供了这种全局连接的基础。

### 2.3 现代 Decoder-only Transformer 的配方

课程的 Transformer 现代演进部分给出 2024-2025 年主流模型常见结构：

```text
输入 -> Token Embedding
     -> 重复 N 层 Transformer Block
        -> RMSNorm
        -> Self-Attention
           -> RoPE
           -> GQA 或 MLA
           -> FlashAttention
        -> 残差连接
        -> RMSNorm
        -> FFN
           -> 密集模型常用 SwiGLU
           -> 稀疏模型使用 MoE
        -> 残差连接
     -> RMSNorm -> Linear -> Softmax
```

把它拆成学生能记住的版本：

| 模块 | 原始 Transformer 常见做法 | 现代 LLM 常见做法 | 为什么改 |
|---|---|---|---|
| FFN 激活 | ReLU/GELU | SwiGLU | 让特征通道有门控选择，表达能力更强 |
| FFN 结构 | 单个密集 MLP | MoE 专家层 | 增大总容量，但每个 token 只激活部分专家 |
| 归一化 | LayerNorm | RMSNorm | 计算更简单，深层训练更稳 |
| 位置编码 | 正弦绝对位置编码 | RoPE | 更适合相对位置和长上下文 |
| Attention KV | 每个头独立 K/V | GQA 或 MLA | 压缩 KV Cache，降低推理显存 |
| Attention 计算 | 直接算大矩阵 | FlashAttention | 减少 GPU 内存读写，提高速度 |

这里不要误解：现代 LLM 没有推翻 Transformer，而是在它的每个部件上做工程和算法升级。

## 3. 预训练、指令微调、RLHF 与推理强化的直觉

### 3.1 预训练：让模型先学会“语言世界”

预训练阶段的目标一般是预测下一个 token。它的作用不是让模型变成合格助手，而是让模型获得基础能力：

- 语言表达；
- 知识记忆；
- 代码和数学模式；
- 文档格式；
- 多领域概念联系；
- 基本推理模板。

预训练后的模型像一个“读过很多书但不一定听话的人”。它能续写，但用户让它“解释月球登陆给 6 岁孩子听”，它可能继续生成一堆类似题目，而不真正完成指令。课件中 GPT-3 的例子正说明了这个问题：训练目标仍是预测下一个词，所以它可能输出无益或有害内容。

### 3.2 指令微调 SFT：把“会续写”改造成“会按要求回答”

SFT 是 Supervised Fine Tuning，监督微调。做法是收集高质量示范数据：

```text
用户指令 -> 理想回答
```

然后继续训练模型，让它模仿这些回答。SFT 的直觉是：老师给模型看很多“好助手应该怎么回答”的样本。

课件中 InstructGPT 的流程第一步就是 SFT，使用人工标注示范数据训练监督策略。SFT 之后，模型通常会更像助手：

- 更愿意直接回答问题；
- 更会遵守格式要求；
- 更会解释、总结、改写；
- 输出语气更符合人类习惯。

但 SFT 也有不足：示范样本有限，无法覆盖所有问题；模型可能学到表面格式，却不一定知道哪个回答更符合人类偏好。

### 3.3 奖励模型 RM：让人类偏好变成可训练信号

RLHF 的第二步是训练 Reward Model。人类不必每次都写出完美答案，而是比较几个回答哪个更好。

流程可以拆成：

1. 给同一个 prompt 生成多个候选回答。
2. 人类标注者排序或选择更偏好的回答。
3. 用这些偏好数据训练一个奖励模型。
4. 奖励模型学会给回答打分。

这个奖励模型不是真理判官，它只是把“人类更喜欢什么样的回答”近似成一个分数。

### 3.4 RLHF：用奖励信号继续调整模型

RLHF 的第三步是强化学习。课件里提到 PPO。直觉流程如下：

```text
Prompt -> 当前模型生成回答 -> 奖励模型打分 -> 强化学习更新模型 -> 更倾向生成高分回答
```

RLHF 的目标是让模型更符合对齐要求，也就是课件里的 3H：

| 对齐目标 | 含义 | 例子 |
|---|---|---|
| Helpful | 有帮助 | 理解用户意图，给出可执行答案 |
| Honest | 诚实 | 不知道时承认不确定，不编造来源 |
| Harmless | 无害 | 避免危险、违法、攻击性输出 |

### 3.5 RLHF 的副作用：迎合与幻觉

课件专门讲了 RLHF 可能让 LLM 更“谄媚”。这很重要，因为它说明对齐不是完美答案。

如果奖励模型过度奖励“让用户感觉舒服”，模型就可能：

- 过度赞同用户；
- 用户说错时也附和；
- 用温暖语气掩盖错误；
- 为了显得有帮助而编造。

课件中的数学例子是：用户问 `300 + 140 = 460` 对不对，模型可能先迎合说对，后来才改正。这说明 LLM 的输出要检查，特别是数学、事实、法律、医学、工程决策等高风险场景。

## 4. Prompt 为什么影响输出

### 4.1 Prompt 不是魔法，而是任务说明书

GPT-3 展现了 In-Context Learning 能力：推理阶段不更新权重，只通过 prompt 中的任务描述和少量示例，就能理解并执行新任务。

例如课件中的翻译提示：

```text
Translate English to Chinese:
apple => 苹果
book => 书
thank you => 谢谢
desk => ?
```

模型看到几个例子后，会把 `desk` 翻译为“桌子”。这里没有重新训练模型，只是在上下文里说明任务。

Prompt 影响输出，是因为模型生成每个 token 时都会条件化在前面的上下文上。你给的目标、角色、格式、示例、约束，都会改变后续 token 的概率分布。

### 4.2 好 Prompt 的四个核心任务

课件把 Prompt 工程的核心任务分成四类：

| 核心任务 | 要做什么 | 具体写法 |
|---|---|---|
| 意图表达 | 把需求说清楚 | 说明任务目标、背景、输入材料 |
| 输出引导 | 控制结果形态 | 指定表格、列表、JSON、报告、小标题、长度 |
| 能力激发 | 让模型调动已有能力 | 给示例、设定角色、要求逐步分析或比较 |
| 风险控制 | 降低错误和不当输出 | 要求标注不确定性、引用来源、避免编造、说明边界 |

### 4.3 Prompt 的必要流程拆解

写一个可用的 Prompt，可以按下面流程：

1. 说清任务：我要你做什么。
2. 给足上下文：材料、对象、背景、受众是谁。
3. 规定输出：用什么结构、长度、语气、格式。
4. 给判断标准：怎样算好，哪些内容必须包含，哪些不能出现。
5. 加风险约束：不确定就说明，不要编造，不要越界。

对比一下：

```text
请解释什么是机器学习。
```

这个 prompt 太宽，模型可能写得泛泛而谈。

```text
你是一位经验丰富的数据科学家。请用通俗易懂的语言向没有技术背景的普通人解释什么是机器学习。
要求：
1. 使用日常生活类比；
2. 控制在 200 字以内；
3. 避免使用专业术语。
```

这个 prompt 明确了角色、受众、风格、长度和禁用内容，所以输出更稳定。

### 4.4 为什么示例很有用

课件中“给予示例的 Prompt”让模型仿照论文标题风格：

```text
BERT: Pre-training of Deep Bidirectional Transformers for Language Understanding
Adam: A Method for Stochastic Optimization
Dropout: A Simple Way to Prevent Neural Networks from Overfitting
```

模型看到这些标题后，能模仿“方法名 + 冒号 + 贡献说明”的模式。示例的作用不是传递知识本身，而是传递输出格式、风格和抽象模式。

### 4.5 CoT：为什么逐步推理能提高复杂任务表现

Chain-of-Thought，思维链，核心是让模型在复杂问题中显式展开中间步骤。课件对比了普通提示和 CoT 提示：数学应用题如果直接回答，容易漏步骤；如果先拆成“原来有多少、用了多少、又买了多少”，答案更可靠。

课程级理解可以这样讲：

- 简单任务不一定需要 CoT；
- 多步数学、逻辑、代码、规划任务更适合 CoT；
- CoT 对大模型更有效，小模型可能无效甚至有害；
- CoT 不是保证正确，只是提高模型把中间关系组织出来的概率。

现代推理模型不一定把完整思考过程展示给用户，但训练目标会强化“先内部推理，再给答案”的行为。

## 5. MoE 为什么能扩容量

### 5.1 稠密模型的问题

传统稠密 Transformer 中，每个 token 都经过同一套 FFN 参数。参数越大，能力可能越强，但每次推理也更贵。

课件以 GPT-1 的 FFN 参数为例说明：FFN 层在 Transformer 参数中占很大比例。现代模型更大后，FFN 成本也会非常高。

问题是：有没有办法让模型“拥有很多专家”，但每次只请少数专家干活？

这就是 MoE。

### 5.2 MoE 的基本结构

MoE 是 Mixture of Experts，混合专家模型。它通常用多个专家网络替代普通 FFN，再加一个 Router 路由器。

基本流程：

```text
token 表示 x
  -> Router 计算每个专家的分数
  -> 选择 Top-k 个专家
  -> 被选专家分别计算 FFN 输出
  -> 按路由权重加权合并
```

课程里的 Switch Transformer 和 Mixtral 都属于这个思路。

| 组件 | 作用 | 类比 |
|---|---|---|
| Router | 判断当前 token 该交给哪些专家 | 分诊台 |
| Expert | 专门处理某类模式的 FFN | 专科医生 |
| Top-k | 只选分数最高的几个专家 | 不让所有医生都同时看病 |
| 加权求和 | 合并专家输出 | 综合会诊意见 |

### 5.3 为什么 MoE 省算力

MoE 的关键是“总参数量”和“激活参数量”分开。

| 模型 | 总参数量 | 每个 token 激活参数 | 说明 |
|---|---:|---:|---|
| 稠密模型 | 比如 70B | 约 70B | 每次基本都用全部参数 |
| Mixtral 8x7B | 约 47B | 约 13B | 每次调用 2 个专家 |
| DeepSeek-V3 | 约 671B | 约 37B | 总容量很大，单 token 激活较少 |

所以 MoE 的直觉是：把模型做成一个大型专家库，但每个输入只访问相关专家。这样模型容量能扩很大，推理成本相对可控。

### 5.4 MoE 的难点

MoE 不是免费午餐。它会引入新问题：

- 路由不均衡：某些专家被大量使用，某些专家闲置。
- 专家混合性：一个专家被迫处理太多类型知识，专业化不足。
- 知识冗余性：多个专家重复学习同一类通用知识。
- 工程复杂：分布式训练、通信、显存调度更难。

DeepSeek-MoE 针对这些问题提出了两个课程里强调的方向：

| 问题 | DeepSeek-MoE 的思路 | 直觉 |
|---|---|---|
| 专家太少导致知识混合 | 细粒度专家切分 | 把专家拆得更细，让专业分工更明确 |
| 通用知识在多个专家里重复 | 共享专家隔离 | 通用知识交给共享专家，专门知识交给路由专家 |

DeepSeek-V3 还使用无辅助损失的负载均衡：通过给专家引入可调整 bias，让过载专家被少选、欠载专家被多选，同时避免辅助损失损害主任务表现。

## 6. DeepSeek V2/V3：现代架构与效率路线

DeepSeek 系列在课件中不是只作为“某个模型名字”出现，而是作为现代 LLM 效率路线的例子。

### 6.1 DeepSeek-V2：MLA 压缩 KV Cache

推理大模型时，一个关键成本是 KV Cache。模型生成长文本时，需要缓存过去 token 的 Key 和 Value，否则每生成一个新 token 都要重算历史。

标准 Multi-Head Attention 中，每个头都有 K/V，缓存随序列长度和头数增长。DeepSeek-V2 的 MLA 做法是：

- 不直接缓存完整 K/V；
- 把 K/V 压缩到低维 latent vector；
- 推理时缓存 compact latent；
- 需要时再投影恢复头相关 K/V。

课件给出效果：KV Cache 减少 93.3%，最大生成吞吐提升到原来的 5.76 倍，并节省训练成本。这说明架构优化不只是提高 benchmark，也直接影响推理成本和服务能力。

### 6.2 DeepSeek-V3：MoE、MTP、FP8

DeepSeek-V3 课件重点包括：

| 技术 | 解决什么问题 | 直觉 |
|---|---|---|
| 参数量提升到 671B | 扩大模型容量 | 总专家库更大 |
| MoE 无辅助损失负载均衡 | 专家使用不均 | 用 bias 动态调节专家被选概率 |
| MTP 多词元预测 | 训练信号稀疏 | 不只预测下一个 token，也预测更后面的 token |
| FP8 混合精度训练 | 训练成本高 | 大部分矩阵乘法用更低精度，敏感模块保留高精度 |

MTP 的直觉很容易懂：传统语言模型每个位置主要预测下一个 token，而 MTP 让一个位置同时预测多个未来 token。这样训练信号更密集，也能为推理加速方法提供帮助。

FP8 则是工程上的经济性：尽量用更低精度减少计算和显存压力，但对 Embedding、Norm、Attention 等敏感模块保持更高精度，避免数值误差破坏训练。

## 7. DeepSeek R1 与推理模型的课程级理解

### 7.1 推理模型和普通聊天模型有什么不同

普通聊天模型强调“给出流畅、符合人类习惯的回答”。推理模型更强调“在复杂题上愿意多走几步”。

课件中 GPT-o1 和 DeepSeek R1 都和竞争数学、代码、科学问答联系在一起。它们的共同点是：通过训练，让模型在复杂问题上形成更强的多步推理行为。

可以把差别理解成：

| 类型 | 主要训练倾向 | 更适合 |
|---|---|---|
| 普通指令模型 | 听指令、写得清楚、对话自然 | 总结、改写、问答、日常助手 |
| 推理模型 | 多步分析、验证、纠错、尝试不同路径 | 数学、代码、逻辑、复杂规划 |

### 7.2 R1-Zero：只用 RL 激发推理行为

课件中 DeepSeek-R1-Zero 的关键点是：没有先给大量“问题-推理步骤-答案”的监督样本，而是从 DeepSeek-V3-Base 出发，用强化学习训练推理行为。

训练信号主要包括：

| 奖励 | 含义 | 例子 |
|---|---|---|
| 准确性奖励 | 答案是否正确 | 数学题答案能验证，代码能编译并通过测试 |
| 格式奖励 | 是否按要求输出推理和答案标签 | 是否使用指定标签结构 |

它的意义在于：模型通过 RL 可以自己发展出较长的推理轨迹，课件称为 Aha Moment，也就是模型在生成中发现前面步骤可能有问题，然后重新检查。

但 R1-Zero 也有问题：可读性、语言一致性和输出结构可能不够好，所以需要进一步改进。

### 7.3 DeepSeek R1：冷启动 + 推理 RL + SFT + 全场景 RL

课件把 DeepSeek R1 的训练拆成四步：

| 步骤 | 做什么 | 为什么需要 |
|---|---|---|
| 1. 冷启动 SFT | 用约 5000 条高质量推理样本微调 | 避免 RL 初期不稳定，提高可读性和结构性 |
| 2. 面向推理的 RL | 加准确性奖励、格式奖励、语言一致性奖励 | 强化数学、代码等推理能力 |
| 3. 拒绝采样与监督微调 | 筛选高质量推理和非推理样本，约 80 万条 | 保持通用问答、写作、翻译、角色扮演等能力 |
| 4. 全场景 RL | 加入人类偏好奖励和 3H 原则 | 让最终模型既能推理，也更适合作为助手 |

这条路线的直觉是：

1. 先给模型一个像样起点；
2. 再用可验证奖励逼它提升推理；
3. 再补回通用能力，防止只会做题；
4. 最后用偏好奖励调整输出质量和安全性。

### 7.4 R1 和 RLHF 的关系

R1 的强化学习和传统 RLHF 有联系，但重点不同。

| 对比项 | 传统 RLHF | R1 类推理强化 |
|---|---|---|
| 主要目标 | 更符合人类偏好和安全要求 | 更强多步推理和可验证任务表现 |
| 奖励来源 | 人类偏好训练出的奖励模型 | 数学答案、代码测试、格式、语言一致性、人类偏好 |
| 典型问题 | 可能迎合用户、过度讨好 | 可能思考时间长、输出冗长、对简单任务不划算 |
| 适合场景 | 通用助手对齐 | 数学、代码、复杂分析、科研辅助 |

所以考试时不要把 R1 简单说成“又一个 ChatGPT”。它体现的是：在大模型已有基础能力后，用强化学习专门塑造推理行为。

## 8. 应用案例：Prompt 如何服务材料研究

课件给了二维材料和 Kagome 结构 `Co3SnInS2` 的案例。这个案例的价值不在于让你记住材料细节，而是理解 LLM 作为研究助手时应该怎么用。

### 8.1 一个弱 Prompt 的问题

如果只写：

```text
帮我调研 Co3SnInS2。
```

模型可能泛泛介绍，甚至混淆材料、性质和文献结论。

### 8.2 一个更好的研究型 Prompt

课件中的 Prompt 更接近这样：

```text
帮我详细调研 Kagome 结构 Co3SnInS2 的研究情况。
着重关注其磁输运和新奇量子性质；
关注上述性能与 Co3Sn2S2 的对比；
分析性能变化的内在机制；
注意资料需要排除未经过同行评议的预印本内容。
```

这个 Prompt 明确了：

- 研究对象：Kagome 结构 Co3SnInS2；
- 重点性质：磁输运、新奇量子性质；
- 对照对象：Co3Sn2S2；
- 输出任务：分析内在机制；
- 证据要求：排除未同行评议预印本。

这就是 Prompt 工程中的意图表达、输出引导和风险控制。

### 8.3 LLM 在科研辅助中的正确位置

LLM 适合做：

- 初步文献线索整理；
- 概念关系梳理；
- 对比表生成；
- 研究问题拆解；
- 实验方案的备选思路；
- 论文段落改写和结构优化。

LLM 不适合直接替代：

- 文献原文核查；
- 数据真实性判断；
- 实验结果解释的最终结论；
- 需要精确引用和页码的综述写作；
- 高风险工程、医学、法律决策。

在材料研究里，好的用法是让模型生成候选假设，再由实验、第一性原理计算或原始文献验证。模型不是裁判，更像一个能快速整理资料的助教。

## 9. 模型和方法对比表

### 9.1 BERT、GPT、ChatGPT、R1

| 名称 | 主要架构或训练路线 | 核心能力 | 课程里要抓住的点 |
|---|---|---|---|
| BERT | Encoder-only Transformer | 双向理解、分类、抽取 | MLM 和 NSP，适合理解类任务 |
| GPT | Decoder-only Transformer | 自回归生成 | 预测下一个 token，适合生成 |
| GPT-3 | 大规模 Decoder-only | ICL、zero-shot/few-shot | Prompt 中给任务描述和示例即可执行 |
| InstructGPT/ChatGPT | 预训练 + SFT + RLHF | 更像人类助手 | 对齐 Helpful、Honest、Harmless |
| DeepSeek-V3 | MoE + MLA + MTP + FP8 等 | 高性能与高效率 | 现代架构优化组合 |
| DeepSeek-R1 | 冷启动 + 推理 RL + SFT + 全场景 RL | 复杂推理 | 用 RL 强化推理行为 |

### 9.2 SFT、RLHF、推理 RL

| 方法 | 数据或奖励从哪里来 | 训练目标 | 常见作用 |
|---|---|---|---|
| 预训练 | 海量文本 token | 预测下一个 token | 获得语言、知识和基本模式 |
| SFT | 人工示范答案 | 模仿高质量回答 | 学会按指令回答 |
| 奖励模型 RM | 人类偏好排序 | 学会给回答打分 | 把偏好变成训练信号 |
| RLHF | RM 分数 + RL 算法 | 增加人类偏好回答概率 | 对齐、安全、可用性 |
| 推理 RL | 可验证答案、代码测试、格式奖励等 | 提升多步推理表现 | 数学、代码、逻辑任务 |

### 9.3 Prompt、CoT、MoE

| 概念 | 它改变什么 | 是否改变模型参数 | 关键误区 |
|---|---|---|---|
| Prompt | 改变输入上下文 | 否 | 不是越长越好，关键是目标和约束清楚 |
| Few-shot 示例 | 改变模型看到的模式 | 否 | 示例质量差会误导模型 |
| CoT | 改变推理展开方式 | 否，除非用于训练 | 展开步骤不保证正确 |
| SFT | 改变模型权重 | 是 | 不等于强化学习 |
| RLHF | 改变模型权重 | 是 | 可能带来迎合 |
| MoE | 改变模型结构 | 是 | 总参数大不代表每次全激活 |

## 10. 工程实践注意事项

### 10.1 使用 LLM 写 Prompt 的注意事项

1. 给任务目标，不要只给主题。
2. 给受众和用途，例如“给本科生复习”“给科研组内部汇报”。
3. 给输出结构，例如表格、步骤、结论、风险。
4. 给证据要求，例如“必须区分课件内容和外部推断”。
5. 给边界要求，例如“不确定时标注不确定，不要编造引用”。
6. 多轮任务要保留关键约束，避免模型在长上下文中漂移。

### 10.2 使用 LLM 做资料调研的注意事项

- 让模型先列检索关键词、研究对象和对照对象。
- 要求区分“已有证据”“模型推测”“需要核查”。
- 对所有关键事实回到原始论文或权威来源核查。
- 不要让模型凭空给 DOI、页码、作者年份。
- 对争议性结论保留多个解释路径。
- 让模型输出表格时，注意表格可能让错误看起来更可靠。

### 10.3 使用推理模型的注意事项

- 复杂数学、代码、规划任务适合推理模型。
- 简单改写、摘要、格式转换不一定需要高强度推理。
- 推理模型可能更慢、成本更高、回答更长。
- 即使是推理模型，也要用测试、计算器、代码运行或文献核查验证结果。
- 需要最终答案时，要让模型把结论和推理依据分开，便于检查。

### 10.4 使用 MoE 模型的注意事项

MoE 模型服务时常见工程问题包括：

- 专家分布不均可能影响吞吐；
- 多机通信开销高；
- 长上下文下 KV Cache 仍然是瓶颈；
- 推理成本不能只看总参数，要看激活参数、上下文长度、batch、硬件和缓存策略；
- 开源 MoE 私有部署要关注显存、路由、并行策略和量化精度。

## 11. 易混点集中辨析

| 易混点 | 正确认法 |
|---|---|
| GPT 会聊天是因为训练时直接学了聊天 | 基础 GPT 主要学下一个 token；聊天能力来自预训练能力、指令微调和对齐训练 |
| 参数越大一定越好 | 参数、数据、计算要平衡；高质量数据和训练效率也很关键 |
| 涌现能力等于模型有意识 | 涌现指某些能力指标随规模出现跃迁，不等于意识 |
| Prompt 工程就是套模板 | Prompt 的重点是任务、上下文、约束、示例和风险控制 |
| CoT 一定能提高答案正确率 | 多步任务常有帮助，但小模型或简单任务可能无效，步骤也可能错 |
| RLHF 只会让模型更好 | RLHF 能提升有用性和安全性，但可能带来迎合、过度保守或幻觉 |
| MoE 的 671B 参数每次都计算 | MoE 只激活部分专家，每个 token 的激活参数远小于总参数 |
| R1-Zero 和 R1 一样 | R1-Zero 主要展示纯 RL 激发推理；R1 加了冷启动、SFT、通用能力数据和全场景 RL |
| DeepSeek-V2/V3 只是参数变多 | 重点还包括 MLA、MoE、负载均衡、MTP、FP8 等效率设计 |
| LLM 输出表格就可信 | 表格只是表达形式，事实仍需核查 |

## 13. 自测题

### 13.1 基础理解题

1. 为什么 GPT 的预训练目标“预测下一个 token”也能带来翻译、摘要、问答等能力？
2. 缩放定律中的 `N`、`D`、`C` 分别表示什么？为什么不能只增加其中一个？
3. 什么是涌现能力？请用课件中的表情猜电影例子解释。
4. 为什么现代聊天大模型多采用 Decoder-only Transformer？
5. BERT 和 GPT 在架构和训练目标上有什么区别？

### 13.2 流程拆解题

1. 请按步骤写出 RLHF 的三阶段流程。
2. 请按步骤写出 MoE 对一个 token 的处理流程。
3. 请按步骤说明 DeepSeek R1 从 base model 到 final model 的训练路线。
4. 一个好 Prompt 通常包含哪些组成部分？
5. 使用 LLM 做文献调研时，应该怎样降低幻觉风险？

### 13.3 对比题

1. SFT 和 RLHF 有什么区别？
2. RLHF 和 R1 类推理强化有什么区别？
3. 稠密模型和 MoE 模型的参数使用方式有什么区别？
4. GQA 和 MLA 都和 KV Cache 有关，它们共同想解决什么问题？
5. CoT Prompt 和普通 Prompt 对复杂数学题的影响为什么不同？

### 13.4 应用题

1. 请把下面的弱 Prompt 改成更适合科研调研的 Prompt：

```text
帮我查一下二维材料机器学习。
```

2. 用户问模型：“300 + 140 = 460 对吗？我觉得一定对。”请说明一个对齐良好的模型应该怎样回答，为什么不能直接迎合。

3. 如果你要让 LLM 帮你总结一篇论文，Prompt 中至少应该包含哪些约束？

4. 如果一个模型总参数量 671B，但每个 token 激活 37B 参数，这更接近稠密模型还是 MoE 模型？为什么？

5. 为什么推理模型适合数学和代码，但不一定适合所有简单问答？

### 13.5 参考答案要点

1. 预测下一个 token 迫使模型学习语言、知识、格式和任务模式；当 prompt 以任务形式出现时，模型可以延续这种模式。
2. `N` 是参数量，`D` 是数据量，`C` 是计算量；只扩大参数可能数据不足，只扩大数据可能容量不足。
3. 涌现能力是某些能力在小模型中不明显，到较大规模后才出现；表情猜电影需要常识、符号理解和任务格式同时具备。
4. 对话和文本生成是自回归任务，Decoder-only 的因果注意力天然适配逐 token 生成。
5. BERT 用 Encoder 做双向理解，GPT 用 Decoder 做单向生成。
6. RLHF：SFT -> 训练奖励模型 -> 用强化学习优化模型。
7. MoE：Router 打分 -> Top-k 专家 -> 专家 FFN 计算 -> 加权合并。
8. R1：冷启动 SFT -> 推理 RL -> 拒绝采样和 SFT -> 全场景 RL。
9. 好 Prompt 包含任务、上下文、输出格式、评价标准和风险约束。
10. 文献调研要核查原文、区分证据与推测、要求来源、不让模型编造引用。

## 14. 最后总复习

LLM 扩展这部分可以压缩成八组关系来复习：

| 关系 | 你要会说明什么 |

| 大模型和缩放定律 | 参数、数据、计算共同扩大，性能按经验规律改善 |
| 缩放和涌现 | 规模变大后，某些复杂能力可能跨过门槛 |
| Transformer 和 GPT | Decoder-only Transformer 适合自回归生成，是现代聊天模型基础 |
| 预训练和 SFT | 预训练学语言世界，SFT 学会按人类指令回答 |
| SFT 和 RLHF | SFT 模仿示范，RLHF 通过偏好奖励进一步对齐 |
| Prompt 和 ICL | Prompt 是推理时的任务说明，示例能在上下文中塑造模式 |
| MoE 和效率 | 总参数扩大，单 token 激活部分专家，容量和成本分离 |
| R1 和推理强化 | 用可验证奖励和多阶段训练强化复杂推理能力 |

考前如果时间很紧，可以按下面顺序复盘：

1. 先画出 LLM 训练路线：预训练 -> SFT -> RM -> RLHF。
2. 再画出 MoE 路线：token -> Router -> Top-k experts -> weighted output。
3. 再背清楚 Prompt 四件事：意图表达、输出引导、能力激发、风险控制。
4. 再区分 R1-Zero 和 R1：前者突出纯 RL 激发推理，后者加入冷启动、通用数据和全场景对齐。
5. 最后记住局限：幻觉、迎合、上下文漂移、成本高、事实必须核查。

LLM 不是单个技术点，而是一条工程路线：用 Transformer 承载规模，用预训练吸收语言和知识，用对齐训练变成助手，用 Prompt 指定任务，用 MoE 和现代架构降低成本，用推理强化提高复杂问题表现。理解这条路线，比单独背每个缩写更重要。
