## 全局学习路线图

学习 NLP 时，最容易乱的地方是名词很多：分词、词表、词向量、语言模型、RNN、Attention、Transformer、BERT、GPT。它们不是并列的一堆概念，而是一条逐步解决问题的路线。

```text
NLP 到底处理什么
    ↓
文本为什么不能直接进入模型
    ↓
把文本拆成 token，再映射到词表编号
    ↓
把编号变成向量：BOW、one-hot、word embedding
    ↓
语言模型：估计一句话或下一个词的概率
    ↓
N-gram：用有限上下文做统计估计
    ↓
NNLM：用词向量和神经网络预测下一个词
    ↓
RNN/LSTM：按顺序读文本，保存历史信息
    ↓
Seq2Seq：一个序列变成另一个序列
    ↓
Attention：生成每一步时动态查看输入重点
    ↓
Transformer：用自注意力并行建模序列关系
    ↓
典型任务：分类、生成、问答、检索、抽取、推断
    ↓
预训练模型：先在大语料上学通用语言知识，再迁移到具体任务
    ↓
考前复盘：公式、流程、易混点、自测题
```

你可以把 NLP 的主线理解成一个问题：

```text
人写出来的是文字，模型能处理的是数字。
NLP 的大部分技术，都在解决“怎样把文字变成有用的数字，并让模型理解这些数字之间的关系”。
```

## 1. NLP 到底处理什么

NLP 是 Natural Language Processing，自然语言处理。这里的“自然语言”指人类日常使用的语言，比如中文、英文、论文摘要、聊天记录、新闻、问答、评论、搜索查询。

NLP 处理的不是“语言学理论本身”，而是让计算机完成和语言有关的任务。

常见任务包括：

| 任务 | 输入 | 输出 | 例子 |
|---|---|---|---|
| 文本分类 | 一段文本 | 类别 | 判断影评是好评还是差评 |
| 情感分析 | 评论、微博、弹幕 | 情感标签 | 积极、消极、中性 |
| 命名实体识别 | 一句话 | 实体位置和类型 | 找出人名、机构名、地点 |
| 自然语言推断 | 前提 + 假设 | 关系类别 | 蕴含、矛盾、中立 |
| 机器翻译 | 源语言句子 | 目标语言句子 | 英文翻成中文 |
| 文本摘要 | 长文本 | 短摘要 | 新闻摘要、论文摘要 |
| 问答 | 问题 + 文档 | 答案 | 从段落中找答案 |
| 检索 | 查询词 | 相关文档 | 搜索引擎返回结果 |
| 文本生成 | 前文或指令 | 后续文本 | 续写、改写、生成回复 |

这些任务看起来不同，但底层通常都会经历类似的步骤：

```text
原始文本
→ 清洗和规范化
→ 分词或切分 token
→ 映射为编号
→ 转成向量
→ 输入模型
→ 输出类别、位置、概率或生成文本
```

## 2. 文本为什么不能直接进模型

神经网络里最基本的运算是矩阵乘法、加法、非线性函数。它们处理的是数字。

比如 MLP 的一层可以写成：

$$
h = f(Wx + b)
$$

这里的 \(x\)、\(W\)、\(b\)、\(h\) 都必须是数值张量。可是文本是字符和词：

```text
我 今天 想 吃 苹果
```

模型不能直接对“我”和“苹果”做矩阵乘法。我们必须先把文本变成数字。

### 2.1 文本和图像的差别

图像天然比较容易变成数字。一张 RGB 图像可以看成三维数组：

```text
高度 × 宽度 × 通道
```

每个像素都有数值，比如 0 到 255。

文本不一样。文本的基本单位不是天然连续数值，而是离散符号：

```text
我、你、材料、科学、apple、book、[MASK]
```

这些符号之间不能直接相加。比如：

```text
苹果 + 香蕉 = ?
苹果 × 桌子 = ?
```

从数学上看，这些操作没有自然定义。所以 NLP 的第一步通常是：给每个语言单位一个可计算的表示。

### 2.2 文本还有三个额外麻烦

第一，长度不固定。

```text
好。
这部电影虽然前半段节奏有点慢，但是后半段非常精彩。
```

两句话长度差很多，但模型训练时通常希望组成 batch。于是需要 padding、mask、截断等处理。

第二，顺序很重要。

```text
我不喜欢这部电影。
我喜欢这部电影，不差。
```

词差不多，但顺序和搭配变了，意思就变了。

第三，同一个词在不同上下文里意思可能不同。

```text
苹果 很甜。
苹果 发布了新产品。
```

第一个“苹果”是水果，第二个可能是公司。只看词本身不够，还要看上下文。

## 3. 分词、词表和 token

### 3.1 什么是 token

token 是模型处理文本时的基本单位。它可以是字、词、子词，也可以是特殊符号。

例如：

```text
原句：材料科学很有趣

按字切分：材 / 料 / 科 / 学 / 很 / 有 / 趣
按词切分：材料科学 / 很 / 有趣
按子词切分：材料 / 科学 / 很 / 有趣
```

英文也类似：

```text
unbelievable
可以作为一个词，也可以切成 un / believe / able
```

不同切法会影响词表大小、未知词比例和模型学习难度。

### 3.2 词表是什么

词表就是 token 到编号的映射表。

课件中 BOW 例子的词表可以写成：

```text
{
  "材料": 0,
  "科学": 1,
  "很": 2,
  "有趣": 3,
  "新": 4,
  "研究": 5,
  "关注": 6,
  "方向": 7
}
```

有了词表，文本就能变成编号序列：

```text
材料 科学 很 有趣
→ [0, 1, 2, 3]

新 材料 研究 关注 新 方向
→ [4, 0, 5, 6, 4, 7]
```

编号本身只是索引，不代表大小关系。编号 7 不表示“方向”比编号 0 的“材料”更大、更高级或更重要。

### 3.3 特殊 token

实际模型里还会有一些特殊 token：

| token | 常见作用 |
|---|---|
| `[PAD]` | 补齐长度，让 batch 内句子一样长 |
| `[UNK]` | 表示词表外未知 token |
| `[CLS]` | 常用于句子整体表示或分类 |
| `[SEP]` | 分隔两段文本 |
| `[MASK]` | BERT 的遮盖预测任务中使用 |
| `<BOS>` | 生成开始标记 |
| `<EOS>` | 生成结束标记 |

这些符号不是普通词，但模型会把它们当成输入序列的一部分处理。

## 4. 从词表编号到向量表示

把 token 变成编号只是第一步。编号仍然不能直接表示语义。接下来要把编号变成向量。

### 4.1 One-hot 表示

假设词表大小为 8，“材料”的编号是 0，“科学”的编号是 1。

one-hot 表示是一个长度为 8 的向量，只有对应位置是 1，其他位置是 0：

```text
材料 → [1, 0, 0, 0, 0, 0, 0, 0]
科学 → [0, 1, 0, 0, 0, 0, 0, 0]
方向 → [0, 0, 0, 0, 0, 0, 0, 1]
```

one-hot 的优点是简单、明确。缺点也很明显：

- 维度等于词表大小，词表大时向量非常长。
- 向量极其稀疏，大部分位置都是 0。
- 任意两个不同词都是正交的，不能表达语义相似。

例如“苹果”和“香蕉”都属于水果，但 one-hot 看不出它们更相似。

### 4.2 Bag-of-Words：词袋模型

课件中的 Bag-of-Words（BOW）思想是：忽略顺序和语法，只统计词出现了几次。

例子：

```text
文档 1：材料 科学 很 有趣
文档 2：新 材料 研究 关注 新 方向
```

词表：

```text
材料:0, 科学:1, 很:2, 有趣:3, 新:4, 研究:5, 关注:6, 方向:7
```

编码结果：

```text
文档 1 → [1, 1, 1, 1, 0, 0, 0, 0]
文档 2 → [1, 0, 0, 0, 2, 1, 1, 1]
```

第二个向量中第 4 个位置是 2，表示“新”出现了两次。

BOW 的优点：

- 简单，容易实现。
- 对文本分类、检索等任务有时很有效。
- 适合解释“哪些词出现了”。

BOW 的缺点：

- 丢掉词序。
- 丢掉语法关系。
- 难以区分否定、转折、长距离依赖。

例如：

```text
我 喜欢 这部 电影
我 不 喜欢 这部 电影
```

如果只看词频，模型可能知道第二句多了“不”，但很难自然理解“不”修饰的是“喜欢”。如果句子更复杂，BOW 更容易出错。

### 4.3 Word embedding：词向量

NNLM 课件里强调了一个关键转变：不要只把词看成离散编号，而要给每个词学习一个连续向量表示。

可以把词向量理解成一张可训练的查表矩阵：

$$
E \in \mathbb{R}^{|V| \times d}
$$

其中：

- \(|V|\)：词表大小。
- \(d\)：词向量维度。
- \(E[i]\)：编号为 \(i\) 的 token 对应的向量。

流程是：

```text
token
→ 查词表得到编号
→ 在 embedding 矩阵中查对应行
→ 得到 d 维连续向量
```

例如：

```text
苹果 → 编号 15 → E[15] = [0.21, -0.08, 0.73, ...]
香蕉 → 编号 39 → E[39] = [0.18, -0.11, 0.69, ...]
桌子 → 编号 82 → E[82] = [-0.52, 0.34, 0.10, ...]
```

如果模型从语料中学到“苹果”和“香蕉”常出现在类似上下文里，它们的向量就可能更接近。

### 4.4 为什么词向量能表达相似性

词向量不是人工手写出来的，而是在训练任务中慢慢学出来的。

如果语言模型经常看到：

```text
我 想 吃 苹果
我 想 吃 香蕉
我 想 吃 葡萄
```

模型为了预测下一个词，会发现“苹果、香蕉、葡萄”在很多上下文里可以扮演类似角色。训练会推动这些词的向量在某些方向上接近。

这就是神经网络语言模型相对 N-gram 的重要进步：它可以在连续向量空间中表达词与词之间的相似性。

## 5. 语言模型的基本想法

语言模型关心的是一句话有多“像正常语言”，或者给定前文后，下一个 token 应该是什么。

### 5.1 估计整句话的概率

课件中给出的核心思想是：

```text
文本可以看作词元序列：
W = w_1, w_2, ..., w_m
```

语言模型本质上是在估计词序列的联合概率：

$$
P(w_1, w_2, ..., w_m)
$$

根据概率链式法则，可以拆成：

$$
P(w_1, w_2, ..., w_m)
= P(w_1)P(w_2|w_1)P(w_3|w_1,w_2)\cdots P(w_m|w_1,\ldots,w_{m-1})
$$

也就是：

```text
一句话的概率
= 第一个词出现的概率
× 已知第一个词时第二个词出现的概率
× 已知前两个词时第三个词出现的概率
× ...
```

当模型看到：

```text
我 今天 想 吃 __
```

它要判断“苹果”比“桌子”更合理，本质上是在比较：

$$
P(\text{苹果}|\text{我 今天 想 吃})
$$

和

$$
P(\text{桌子}|\text{我 今天 想 吃})
$$

### 5.2 下一个词预测

最经典的语言模型训练目标是下一个词预测：

```text
输入：我 今天 想 吃
目标：苹果
```

模型输出的是词表上每个 token 的概率分布：

```text
苹果: 0.42
香蕉: 0.23
米饭: 0.11
桌子: 0.0003
...
```

训练时常用交叉熵损失。若正确词是 \(w^*\)，模型给出的概率是 \(p(w^*)\)，单个样本损失可以写成：

$$
L = -\log p(w^*)
$$

概率越高，损失越小；概率越低，损失越大。

## 6. N-gram：统计语言模型的代表

N-gram 是早期统计 NLP 的代表。它的核心是：当前词只依赖前面有限个词。

### 6.1 马尔可夫假设

完整条件概率是：

$$
P(w_i|w_1,w_2,\ldots,w_{i-1})
$$

但前文可能很长，直接估计很难。N-gram 做了简化：

$$
P(w_i|w_1,\ldots,w_{i-1})
\approx P(w_i|w_{i-N+1},\ldots,w_{i-1})
$$

也就是只看前 \(N-1\) 个词。

### 6.2 Trigram 例子

如果是 3-gram，也叫 trigram，只看前两个词：

$$
P(w_i|w_1,\ldots,w_{i-1})
\approx P(w_i|w_{i-2}, w_{i-1})
$$

比如：

```text
我 今天 想 吃 苹果
```

预测“苹果”时，trigram 主要看：

```text
吃 苹果
```

或者条件概率：

$$
P(\text{苹果}|\text{想}, \text{吃})
$$

### 6.3 N-gram 的优缺点

| 方面 | 优点 | 问题 |
|---|---|---|
| 可解释性 | 统计频率清楚，容易理解 | 只能看到短上下文 |
| 计算 | 比完整历史容易算 | N 增大后组合数量爆炸 |
| 数据需求 | 小 N 时可用 | 很多词组从未出现，概率估计稀疏 |
| 语义 | 能学到常见搭配 | 不知道“苹果”和“香蕉”语义相近 |
| 长距离依赖 | 基本无能为力 | 前文太远就被截断 |

N-gram 的价值在于：它把语言建模变成了可计算的概率问题。但它仍然把词当成离散符号，没有真正解决语义相似和长上下文问题。

## 7. NNLM：从离散词到连续向量

NNLM 是 Neural Network Language Model，神经网络语言模型。课件中提到的核心想法是：用词向量表示词，再用神经网络预测下一个词。

### 7.1 NNLM 的基本流程

```text
前几个词
→ 查表得到词向量
→ 把这些词向量拼接或组合
→ 输入神经网络
→ 输出下一个词在词表上的概率分布
```

例如要预测：

```text
我 想 吃 __
```

模型会做：

```text
我 → embedding("我")
想 → embedding("想")
吃 → embedding("吃")
拼接成一个向量
送入 MLP
输出 P(下一个词 | 我, 想, 吃)
```

### 7.2 与 N-gram 的关键区别

| 对比点 | N-gram | NNLM |
|---|---|---|
| 词表示 | 离散符号 | 连续词向量 |
| 相似词泛化 | 很弱 | 可以较好泛化 |
| 参数学习 | 统计频率为主 | 通过反向传播学习 |
| 上下文长度 | 固定 N-1 个词 | 也常固定窗口，但表示更灵活 |
| 语义关系 | 难表达 | 可通过 embedding 表达 |

课件中的直觉例子是：N-gram 会把“苹果、香蕉、桌子”看成互不相关的离散符号；NNLM 学到词向量后，“苹果”和“香蕉”更可能靠近，“桌子”则可能远一些。

## 8. RNN 和 LSTM 在 NLP 中的作用

### 8.1 为什么需要 RNN

文本是序列。一个词的含义经常依赖前面的词。

```text
我 原来 以为 这部电影 会很差，结果 ...
```

读到“结果”时，后面的评价可能发生转折。模型需要记住前面读过的内容。

RNN 的思想是：按顺序读，每读一个 token，就更新一次隐藏状态。

标准 RNN 可以写成：

$$
h_t = f(W_{hh}h_{t-1} + W_{xh}x_t + b_h)
$$

其中：

| 符号 | 含义 |
|---|---|
| \(x_t\) | 第 \(t\) 个 token 的输入向量 |
| \(h_{t-1}\) | 上一步的隐藏状态 |
| \(h_t\) | 当前隐藏状态 |
| \(W_{xh}\) | 输入到隐藏状态的权重 |
| \(W_{hh}\) | 历史状态到当前状态的权重 |
| \(f\) | 非线性函数，如 tanh |

处理一句话时：

```text
x_1 → h_1
x_2 + h_1 → h_2
x_3 + h_2 → h_3
...
x_T + h_{T-1} → h_T
```

最后的 \(h_T\) 可以看成整句话的压缩表示，用于分类；每一步的 \(h_t\) 也可以用于序列标注。

### 8.2 RNN 的问题

RNN 的主要问题有三个。

第一，顺序计算慢。

```text
h_5 必须等 h_4 算完
h_4 必须等 h_3 算完
```

这不利于并行训练。

第二，梯度消失或爆炸。

长序列反向传播时，梯度要沿着很多时间步传回去。连续乘很多矩阵后，梯度可能越来越小，也可能越来越大。

第三，长距离依赖难。

如果句子很长，前面重要信息要经过很多步传到后面，中途容易被冲淡。

### 8.3 LSTM 如何改进 RNN

LSTM 可以看成更复杂的 RNN 单元。它引入了 cell state，专门作为长期记忆通道，并用门控制信息流动。

课件中强调了三个门：

| 门 | 作用 |
|---|---|
| 遗忘门 | 决定丢弃哪些旧信息 |
| 输入门 | 决定添加哪些新信息 |
| 输出门 | 决定输出什么样的隐藏状态 |

可以用一个生活化过程理解：

```text
读到新词
→ 判断旧记忆哪些该保留
→ 判断新内容哪些该写入
→ 更新长期记忆
→ 输出当前隐藏状态
```

LSTM 比普通 RNN 更适合处理中等长度的文本序列，但仍然保留顺序计算的瓶颈。

## 9. Seq2Seq：从一个序列到另一个序列

很多 NLP 任务不是输出一个类别，而是输出另一个序列。

例如：

| 任务 | 输入序列 | 输出序列 |
|---|---|---|
| 机器翻译 | Are you free tomorrow? | 你明天有空吗？ |
| 文本摘要 | 一篇长新闻 | 一段短摘要 |
| 简单问答 | 用户问题 | 系统回复 |
| 邮件回复 | 来信内容 | 回复内容 |

Seq2Seq 模型通常由 Encoder 和 Decoder 组成。

### 9.1 Encoder 做什么

Encoder 读取输入序列，把它压缩成内部表示。

```text
输入：Are you free tomorrow?
Encoder 逐词读取
输出：上下文表示
```

如果用 RNN/LSTM，Encoder 会沿着输入顺序更新隐藏状态。

### 9.2 Decoder 做什么

Decoder 根据 Encoder 提供的信息，逐步生成目标序列。

```text
上一步生成：你
当前生成：明天
下一步生成：有空
...
```

生成时通常是自回归的：

```text
已经生成的内容会作为下一步生成的条件
```

### 9.3 固定向量瓶颈

早期 Seq2Seq 常把整句输入压缩进一个固定长度向量。短句还可以，长句就容易丢信息。

比如翻译长句时，Decoder 生成不同词需要关注源句不同部分。如果只能看同一个压缩向量，信息容易挤在一起。

这就引出了 Attention。

---

## 10. Attention：动态读取重点信息

### 10.1 Attention 解决什么问题

普通 Seq2Seq 的问题是：整句输入被压成一个固定向量。Attention 的思路是：Decoder 每生成一步，都可以重新查看输入序列，并给不同位置分配权重。

例如翻译：

```text
Are you free tomorrow?
```

生成“你”时，更关注 `you`；生成“明天”时，更关注 `tomorrow`。

流程可以写成：

```text
当前 Decoder 状态
→ 和 Encoder 每个位置计算相关性
→ 得到注意力权重
→ 对 Encoder 各位置表示加权求和
→ 得到当前步需要的上下文信息
```

### 10.2 Q、K、V 的直觉

Transformer 里常把注意力写成 Q、K、V：

| 名称 | 含义 | 类比 |
|---|---|---|
| Query | 当前想找什么 | 搜索框里的查询 |
| Key | 每个位置用来被匹配的标签 | 文档关键词 |
| Value | 每个位置真正提供的信息 | 文档正文内容 |

匹配时用 Query 和 Key 算相似度；真正取信息时用权重加权 Value。

标准注意力公式是：

$$
\text{Attention}(Q,K,V)=\text{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}\right)V
$$

拆开看：

```text
QK^T
→ 计算每个 Query 和每个 Key 的匹配分数

除以 sqrt(d_k)
→ 防止分数过大，让 softmax 更稳定

softmax
→ 把分数变成权重，每一行权重和为 1

乘以 V
→ 用权重对信息做加权求和
```

### 10.3 Self-Attention

Self-Attention 的 Q、K、V 都来自同一个序列。

也就是说，句子里每个 token 都可以去看句子里的其他 token：

```text
“不” 可以关注 “喜欢”
“苹果” 可以关注 “吃”
“明天” 可以关注 “有空”
```

这比 RNN 逐步传递信息更直接。远处两个词之间不必一步一步传递，可以通过注意力权重直接建立联系。

## 11. Transformer 在 NLP 中的作用

Transformer 的核心是自注意力机制。课件中强调，原始 Transformer 最初是为机器翻译设计的：

```text
Encoder 读入源语言句子
Decoder 自回归生成目标语言句子
```

### 11.1 Transformer Encoder

Encoder 主要用于理解输入序列。

典型结构包括：

```text
输入 embedding + 位置编码
→ 多头自注意力
→ 残差连接 + 层归一化
→ 前馈神经网络
→ 残差连接 + 层归一化
```

Encoder 适合做理解类任务：

- 文本分类
- 自然语言推断
- 命名实体识别
- 抽取式问答
- 检索向量表示

### 11.2 Transformer Decoder

Decoder 主要用于生成序列。

它有一个重要限制：生成当前位置时不能偷看未来 token。因此需要 masked self-attention。

典型生成过程：

```text
输入：<BOS>
输出：今天

输入：<BOS> 今天
输出：天气

输入：<BOS> 今天天气
输出：很好
```

Decoder 适合做生成类任务：

- 文本续写
- 对话回复
- 生成式摘要
- 自回归翻译

### 11.3 Encoder-Decoder

Encoder-Decoder 结构适合输入和输出都是序列的任务。

```text
源句子 → Encoder → 源句表示
目标前缀 → Decoder → 下一个目标 token
```

Decoder 中的 cross-attention 会用当前生成状态去读取 Encoder 输出。

典型任务：

- 机器翻译
- 文本摘要
- 语音识别后的文本生成
- 文本改写

### 11.4 RNN 和 Transformer 的核心差别

| 对比点 | RNN/LSTM | Transformer |
|---|---|---|
| 处理方式 | 按时间步顺序读 | 一次性看整段序列 |
| 长距离依赖 | 需要逐步传递，容易衰减 | 注意力可直接连接远处 token |
| 并行训练 | 较弱 | 较强 |
| 顺序信息 | 天然来自时间步 | 需要位置编码 |
| 适合场景 | 较短序列、资源有限、教学理解 | 现代 NLP 主流架构 |

注意：Transformer 并不是“不需要顺序”。它的 self-attention 本身不含顺序偏好，所以必须通过位置编码或类似机制告诉模型 token 的位置。

## 12. 典型 NLP 任务对比

### 12.1 文本分类

文本分类是把一段文本映射到一个类别。

```text
输入：这部电影节奏很慢，但结尾很感人。
输出：正面 / 负面 / 中性
```

常见流程：

```text
文本
→ token 序列
→ embedding
→ 编码器提取整体表示
→ 分类层
→ softmax 输出类别概率
```

损失函数通常是交叉熵：

$$
L = -\log p(y^*)
$$

其中 \(y^*\) 是正确类别。

### 12.2 序列标注

序列标注是给每个 token 一个标签。

例如命名实体识别：

```text
北京 航空 航天 大学 位于 北京
B-ORG I-ORG I-ORG I-ORG O O B-LOC
```

它和文本分类不同：分类只输出一个整体标签，序列标注要输出一串标签。

### 12.3 生成任务

生成任务要输出新的文本序列。

```text
输入：今天天气很好，我决定去公园散步。刚走到湖边，
输出：看见几只鸭子正在水面上慢慢游过。
```

生成模型通常一步一步预测下一个 token：

$$
P(y_1,\ldots,y_T|x)
= \prod_{t=1}^{T} P(y_t|y_{<t}, x)
$$

如果没有输入 \(x\)，就是纯语言模型续写；如果有输入 \(x\)，就是条件生成。

### 12.4 问答任务

问答有多种形式。

抽取式问答：

```text
输入：问题 + 段落
输出：段落中的起始位置和结束位置
```

例如 SQuAD 风格任务中，模型要在段落里找出答案 span。

生成式问答：

```text
输入：问题
输出：模型生成的一段答案
```

检索增强问答：

```text
问题
→ 检索相关文档
→ 阅读文档
→ 生成或抽取答案
```

### 12.5 检索任务

检索的目标是找到和查询最相关的文档。

传统做法可能用词频、TF-IDF、BM25。神经网络做法会把查询和文档编码成向量，然后比较相似度。

常见相似度是余弦相似度：

$$
\cos(q,d)=\frac{q \cdot d}{\|q\|\|d\|}
$$

其中 \(q\) 是查询向量，\(d\) 是文档向量。

### 12.6 任务对比表

| 任务 | 输出形式 | 常用结构 | 关键难点 |
|---|---|---|---|
| 文本分类 | 一个类别 | Encoder + 分类头 | 抓整体语义 |
| 情感分析 | 情感类别 | Encoder / RNN / CNN | 否定、转折、讽刺 |
| 命名实体识别 | 每个 token 的标签 | Encoder + token 分类 | 边界和实体类型 |
| 自然语言推断 | 关系类别 | Encoder 处理句对 | 判断两句话逻辑关系 |
| 机器翻译 | 目标语言序列 | Encoder-Decoder | 对齐和生成 |
| 文本摘要 | 短文本序列 | Encoder-Decoder | 保留重点、避免遗漏 |
| 抽取式问答 | 答案起止位置 | Encoder + span 预测 | 定位答案边界 |
| 检索 | 文档排序 | 双塔模型 / 交叉编码器 | 相关性表示 |
| 文本续写 | 后续 token | Decoder | 连贯性和条件依赖 |

## 13. 从传统 NLP 到预训练模型的过渡

### 13.1 规则系统阶段

课件中的 ELIZA 和 SHRDLU 代表早期规则 NLP。

ELIZA 的方式大致是：

```text
扫描用户输入
→ 找关键词或短语
→ 匹配规则
→ 套用预先写好的回复模板
```

例如遇到 `I am sad`，系统按规则回应安慰类话语。

SHRDLU 的方式是把自然语言指令转换为积木世界中的操作目标，再检查状态和空间关系，规划机械臂动作。

规则系统的优点：

- 在封闭场景里可控。
- 逻辑清楚，容易解释。
- 不需要大量数据。

规则系统的问题：

- 人类语言太复杂，规则写不完。
- 稍微换一种说法就可能匹配失败。
- 难以迁移到开放领域。

### 13.2 统计 NLP 阶段

统计 NLP 放弃穷举规则，转向从大规模语料中统计规律。

典型方法包括：

- 词频统计
- BOW
- N-gram
- TF-IDF
- 朴素贝叶斯、逻辑回归等传统模型

它的思想是：语言虽然复杂，但大量文本中会出现稳定统计模式。

问题是：统计方法常常依赖表面词频和短窗口，语义泛化能力有限。

### 13.3 神经网络 NLP 阶段

NNLM 开始用词向量和神经网络建模语言。

RNN/LSTM 进一步把文本当作序列处理，能按顺序积累历史信息。

Seq2Seq 和 Attention 让模型能完成翻译、摘要、问答等输入输出都是序列的任务。

Transformer 把自注意力变成核心结构，解决了 RNN 的顺序计算瓶颈，并改善长距离依赖建模。

### 13.4 预训练加微调范式

课件中 BERT 展示了预训练加微调范式。

预训练阶段：

```text
用大量未标注文本训练模型
让模型学习通用语言规律
```

微调阶段：

```text
把预训练模型接到具体任务上
用少量标注数据继续训练
```

BERT 的典型预训练任务包括：

| 任务 | 思想 |
|---|---|
| MLM | 随机遮住一些 token，让模型预测被遮住的词 |
| NSP | 判断两句话是否是上下句关系 |

MLM 例子：

```text
The quick brown fox jumps over the [MASK] dog.
目标：lazy
```

BERT 更偏理解，常用于分类、推断、实体识别、抽取式问答等任务。

GPT 早期模型展示了 decoder-only 的生成式预训练思路：

```text
The weather is
→ very
→ nice
→ today
```

GPT 更偏生成，核心训练目标是根据前文预测下一个 token。

这里需要把握的是“范式变化”：模型不再为每个任务从零开始训练，而是先通过大规模文本学习通用语言表示，再适配具体任务。

## 14. 易混点集中讲

### 14.1 token、词、字不是同一个概念

token 是模型实际处理的单位。它可以等于一个词，也可以是一个字或子词。

中文里“自然语言处理”可以切成：

```text
自然 / 语言 / 处理
```

也可以切成：

```text
自 / 然 / 语 / 言 / 处 / 理
```

模型看到的是 token 序列，不一定是人直觉中的词。

### 14.2 编号不是语义

词表编号只是查表索引。

```text
苹果: 12
香蕉: 13
桌子: 14
```

不能因为编号接近就说语义接近。真正表达语义的是 embedding 向量，而不是编号。

### 14.3 BOW 和 embedding 都是向量，但含义不同

| 表示 | 向量含义 |
|---|---|
| BOW | 整篇文档里每个词出现几次 |
| one-hot | 某个 token 在词表中的位置 |
| embedding | 某个 token 学到的连续语义表示 |

BOW 通常表示一整段文本；embedding 通常表示一个 token，后续还需要通过模型组合成句子表示。

### 14.4 语言模型不是只会生成文本

语言模型的核心是估计 token 序列概率。生成只是它的一种用法。

如果模型能判断：

```text
P(我 今天 想 吃 苹果) > P(我 今天 想 吃 桌子)
```

它就已经学到了一部分语言规律。

### 14.5 RNN 的隐藏状态不是原文复制

RNN 的 \(h_t\) 是压缩后的连续向量，不是把前面所有词原样存起来。压缩就可能丢信息，所以长距离依赖困难。

### 14.6 Attention 权重不是完整解释

Attention 权重能显示模型在某一步更关注哪些位置，但不能简单等同于人类可解释因果。它是模型内部计算的一部分，不是最终解释的全部。

### 14.7 Encoder 和 Decoder 不要混

| 结构 | 更擅长 |
|---|---|
| Encoder-only | 理解输入，如分类、抽取、推断 |
| Decoder-only | 自回归生成，如续写 |
| Encoder-Decoder | 输入序列到输出序列，如翻译、摘要 |

### 14.8 Transformer 不会自动知道顺序

Self-Attention 如果没有位置编码，交换 token 顺序后模型很难区分位置变化。因此 Transformer 需要位置编码或其他位置机制。

## 16. 必要公式汇总

### 16.1 语言模型链式分解

$$
P(w_1,\ldots,w_m)
= \prod_{i=1}^{m}P(w_i|w_1,\ldots,w_{i-1})
$$

含义：一句话的概率可以拆成每一步条件概率的乘积。

### 16.2 N-gram 近似

$$
P(w_i|w_1,\ldots,w_{i-1})
\approx P(w_i|w_{i-N+1},\ldots,w_{i-1})
$$

含义：为了可计算，只看前面有限个词。

### 16.3 RNN 状态更新

$$
h_t=f(W_{hh}h_{t-1}+W_{xh}x_t+b_h)
$$

含义：当前隐藏状态由旧隐藏状态和当前输入共同决定。

### 16.4 自回归生成概率

$$
P(y_1,\ldots,y_T|x)
= \prod_{t=1}^{T}P(y_t|y_{<t},x)
$$

含义：每一步生成都依赖输入和已经生成的前缀。

### 16.5 Scaled Dot-Product Attention

$$
\text{Attention}(Q,K,V)=\text{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}\right)V
$$

含义：先匹配，再归一化成权重，最后按权重取信息。

### 16.6 分类交叉熵

$$
L=-\log p(y^*)
$$

含义：正确类别概率越高，损失越小。

### 17.3 流程题

题目 1：把下面的文本转成模型输入，一般要经过哪些步骤？

材料科学很有趣

参考答案：

文本清洗

题目 2：解释下面公式中每一步在做什么。

$$
\text{Attention}(Q,K,V)=\text{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}\right)V
$$

参考答案：

```text
QK^T：计算 Query 和 Key 的匹配分数
除以 sqrt(d_k)：缩放分数，避免 softmax 过于极端
softmax：把分数变成注意力权重
乘以 V：对 Value 加权求和，得到输出表示
```

题目 3：一个文本分类模型如何从一句话得到类别？

参考答案：

```text
句子
→ token ids
→ embedding
→ Encoder / RNN 编码
→ 取整体表示
→ 线性分类层
→ softmax
→ 类别概率
```

### 17.4 对比题

题目：比较 BOW、RNN、Transformer 对文本顺序的处理方式。

参考答案：

| 方法 | 如何处理顺序 |
|---|---|
| BOW | 基本忽略顺序，只统计词频 |
| RNN | 按顺序逐步读取，隐藏状态传递历史 |
| Transformer | 通过 self-attention 建模任意位置关系，但需要位置编码 |

题目：比较 BERT 式理解模型和 GPT 式生成模型的基本思路。

参考答案：

| 模型范式 | 结构倾向 | 训练目标倾向 | 适合任务 |
|---|---|---|---|
| BERT 式 | Encoder-only | 遮盖词预测等 | 分类、推断、抽取、实体识别 |
| GPT 式 | Decoder-only | 下一个 token 预测 | 续写、生成、对话 |

## 18. 最后总复习

### 18.1 一条主线串起来

NLP 的起点是文字，但神经网络只能处理数字。于是我们先把文本切成 token，再用词表把 token 变成编号，接着用 one-hot、BOW 或 embedding 把文本变成向量。

早期规则系统试图用人工规则理解语言，代表例子有 ELIZA 和 SHRDLU。它们在封闭场景里有效，但遇到开放语言就很难扩展。

统计 NLP 用词频和概率学习语言规律。BOW 把文档变成词频向量，N-gram 用有限上下文估计下一个词概率。这些方法简单可解释，但语义泛化和长距离依赖较弱。

NNLM 用词向量和神经网络预测下一个词，让“苹果”和“香蕉”这类相似词在向量空间中更容易接近。

RNN/LSTM 把文本当作序列，按顺序读取 token，并用隐藏状态保存历史。LSTM 通过门控机制改善长期记忆，但顺序计算慢，长距离信息仍可能传递困难。

Seq2Seq 把一个序列变成另一个序列，适合翻译、摘要和问答。普通 Seq2Seq 把整句压成固定向量，容易形成信息瓶颈。Attention 让 Decoder 每一步动态读取输入中最相关的位置。

Transformer 用 self-attention 作为核心，让序列内部任意位置可以直接建立联系，并通过并行计算提升训练效率。Encoder 更偏理解，Decoder 更偏生成，Encoder-Decoder 更适合输入输出都是序列的任务。

预训练模型把 NLP 推到新的范式：先在大量未标注文本上学习通用语言知识，再通过微调适配分类、推断、实体识别、问答、生成等任务。BERT 代表偏理解的 Encoder-only 路线，GPT 代表偏生成的 Decoder-only 路线。本文只讲到这个过渡点，不继续展开后续专题。

### 18.3 最后用一张表收尾

| 阶段 | 代表方法 | 解决的问题 | 主要不足 |
|---|---|---|---|
| 规则 NLP | ELIZA、SHRDLU | 用人工规则处理语言 | 规则写不完，泛化弱 |
| 统计 NLP | BOW、N-gram | 用频率和概率建模文本 | 丢顺序、语义弱、上下文短 |
| 神经语言模型 | NNLM、embedding | 学习连续语义表示 | 上下文窗口仍有限 |
| 序列模型 | RNN、LSTM | 按顺序保存历史信息 | 顺序计算慢，长依赖困难 |
| 注意力模型 | Seq2Seq + Attention | 动态读取输入重点 | 结构仍可能依赖 RNN |
| Transformer | Self-Attention | 并行建模全局关系 | 需要位置机制，计算量随长度增大 |
| 预训练模型 | BERT、GPT 早期范式 | 通用语言知识迁移到任务 | 需要大量语料和算力 |
